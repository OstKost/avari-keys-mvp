# TASK-004: Master Backend — Управление нодами и ключами клиентов

## 1. Описание задачи (Specific)
Реализовать в Master Backend модуль управления Slave-нодами и выдачи/отзыва конфигураций клиентов:
- Таблица `nodes`: поля `id`, `name`, `type` (`cascade` / `direct`), `api_url`, `api_key`, `is_active`, `created_at`.
- Админские эндпоинты нод:
  - `GET /api/v1/admin/nodes` — список нод с их онлайн-статусом (пинг к Slave `/health`).
  - `POST /api/v1/admin/nodes` — добавление ноды (имя, тип, URL, API ключ).
  - `DELETE /api/v1/admin/nodes/{id}` — удаление ноды.
- HTTP-клиент к Slave API (`apps/backend/internal/client`):
  - Вызовы `CreateClient`, `DeleteClient`, `GetClient`, `HealthCheck` с передачей `X-API-Key`.
- Пользовательские эндпоинты для ключей:
  - `GET /api/v1/nodes` — список доступных активных нод (без показа `api_key`).
  - `GET /api/v1/keys` — список ключей текущего пользователя (с привязкой к ноде).
  - `POST /api/v1/keys` — создание ключа для себя (`node_id`, `device_name`). Master отправляет запрос на Slave, сохраняет запись в SQLite и возвращает `.conf` и QR-код.
  - `GET /api/v1/keys/{id}` — получение `.conf` и QR для существующего ключа (запрашивается со Slave).
  - `DELETE /api/v1/keys/{id}` — удаление ключа (отправка delete на Slave и удаление из SQLite).
- Админский эндпоинт `GET /api/v1/admin/keys` — аудит всех ключей всех пользователей.

## 2. Критерии приемки (Measurable)
- [ ] Добавление ноды с невалидным URL или неверным ключом возвращает информативную ошибку проверки соединения.
- [ ] При запросе ключа от авторизованного активного пользователя создается уникальный префикс имени клиента (например, `u{user_id}_{device_name}`).
- [ ] Обычный пользователь не может удалить или просмотреть ключ другого пользователя (`403 Forbidden`).
- [ ] При удалении ключа пользователем происходит вызов соответствующего Slave API и удаление из базы.
- [ ] Написаны unit- и mock-тесты диспетчера нод и HTTP-клиента.

## 3. Достижимость (Achievable)
Опирается на контракты Slave API из TASK-002 и базу данных из TASK-003.

## 4. Актуальность (Relevant)
Основная функциональность MVP — предоставление пользователю выбора между Каскадным (M0->S1) и Прямым (S2) туннелем в один клик.
