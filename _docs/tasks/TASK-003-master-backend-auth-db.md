# TASK-003: Master Backend — SQLite БД, Аутентификация и Модерация

## 1. Описание задачи (Specific)
Реализовать подсистему хранения данных и аутентификации в Master Backend (`apps/backend/cmd/master`):
- Интеграция SQLite через чистый Go-драйвер (`modernc.org/sqlite` без CGo).
- Схема таблиц: `users`, `nodes`, `client_configs`.
- Автоматическая инициализация учетной записи администратора `Forve` по умолчанию при первом запуске:
  - Генерируется надежный случайный пароль (16+ символов, `crypto/rand`).
  - Пароль хешируется через `bcrypt` и сохраняется в базу данных.
  - Однократно и заметно выводится в лог/консоль учетные данные для первого входа.
  - Поддерживается переопределение через переменные окружения `ADMIN_USER` и `ADMIN_PASSWORD`.
- Регистрация пользователей (`POST /api/v1/auth/register`) с установкой `is_active = 0`.
- Аутентификация (`POST /api/v1/auth/login`) с проверкой `is_active == 1` (если `is_active == 0`, возврат ошибки `403 Forbidden: Account pending admin approval`).
- JWT-токены или безопасные HTTP-only cookie сессии.
- Эндпоинты администратора для управления пользователями:
  - `GET /api/v1/admin/users` — список всех пользователей со статусами.
  - `POST /api/v1/admin/users/{id}/activate` — активация аккаунта.
  - `POST /api/v1/admin/users/{id}/deactivate` — деактивация аккаунта.
  - `DELETE /api/v1/admin/users/{id}` — удаление пользователя.

## 2. Критерии приемки (Measurable)
- [ ] База данных создается автоматически в указанном пути (по умолчанию `./data/avari-master.db`).
- [ ] При первом старте создается админ `Forve`, а в консоль выводится сгенерированный пароль.
- [ ] Пароли хешируются с использованием `bcrypt`.
- [ ] Неактивированный пользователь получает `403 Forbidden` при попытке входа.
- [ ] Администратор может успешно активировать пользователя, после чего тот может войти.
- [ ] Обычный пользователь не имеет доступа к эндпоинтам `/api/v1/admin/*` (`403 Forbidden`).
- [ ] Написаны unit-тесты для репозитория пользователей и HTTP middleware проверки ролей и активности.

## 3. Достижимость (Achievable)
Опирается на надежные Go-библиотеки без внешних CGo-зависимостей.

## 4. Актуальность (Relevant)
Обеспечивает безопасность сервиса и реализацию требования модерации пользователей администратором.
